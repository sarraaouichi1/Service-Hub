9 Key Enhancements
1 Operator & Cell Computer Hierarchy (Core Domain)
1.1 Split Operator vs. Cell Computer Architecture & Multiple Cell Computers
P1 · Critical
Stakeholder Feedback: "The connection details currently shown under the operator should belong to the cell computer. One operator can have multiple cell computers, each with different URLs, IP addresses, ports, and credentials... The platform therefore needs the option to assign multiple cell computers to one operator."
  • Operator-Level Scope: Retain common enterprise/locale attributes strictly at the Operator entity: Country, Language Tag, Currency, Decimal Places, and VAT Percentage.
  • Cell Computer Entity: Create a child repeatable model linked to the Operator. Each cell computer maintains: Identifier/Name (e.g. CC-01, CC-North), URL, Host IP Address, Port, and Connection Credentials.
  • UI Implementation: Provide an interactive "Add Cell Computer" sub-form within the wizard allowing dynamic multi-instance configuration per operator.
2 Facilities Mapping & Service Association
2.1 Facility-to-Cell Computer Reference & Granular Service Selection
P1 · Critical
Stakeholder Feedback: "Each facility needs a reference to its corresponding cell computer. It should be possible to select which service a facility belongs to. A facility used for Validation is not necessarily also used for entervo connect or another smart service. Clarify description."
  • Cell Computer Link: Add an explicit dropdown in each Facility card referencing one of the operator's defined Cell Computers.
  • Per-Facility Service Matrix: Replace global service inheritance with per-facility checkboxes: [x] Validation, [x] entervo connect, [x] smart-web-pay, etc.
  • UI Clarification: Update helper banners to clearly state: "Select only the specific digital services actively enabled at this physical location."
3 Application & Payment Gating
3.1 Conditional Payment Service Provider (PSP) Display
P1 · Critical
Stakeholder Feedback: "A payment service provider is not required for a Validation onboarding. Displaying this field in the Validation workflow could therefore be misleading."
  • Conditional Rendering: If the selected product is exclusively Validation (or non-payment smart services), completely hide the PSP dropdown, merchant ID, and credential fields.
  • Dynamic Validation Schema: Update Zod validation in @service-hub/shared so PSP is strictly required only when payment-handling products (e.g. smart-web-pay) are selected.
4 Product Configuration Overhaul
4.1 Single-Page Consolidated Product View with Quick-Copy Button
P2 · High
Stakeholder Feedback: "...change the products aspect because we will use different excel sheets with newer version and we will change the view of products to make all the steps in one page with a copy button."
  • All-in-One Configuration Page: Consolidate multi-tab product parameters into a clean, collapsible single-page layout for rapid review and editing.
  • One-Click "Copy Configuration" Button: Add a dedicated action button at the top of the product view to instantly copy formatted configuration parameters (or JSON payload) to clipboard.
  • Updated Excel Sheet Parser: Adapt data models and import logic to ingest the new specification spreadsheet versions and new product schema definitions.
5 User Management & Usability
5.1 Saved Draft Restoration & Discovery
P2 · High
Stakeholder Feedback: "I saved the onboarding process as a draft, but I could not find or restore it afterwards."
  • Resume Draft Banner: Display an automatic notification card on the Onboarding Hub dashboard when an active draft is detected in the database.
  • New Project Prompt: When clicking "New Onboarding", prompt the user: "A saved draft exists from [Date]. Would you like to resume or start fresh?"
  • Draft Column & Quick Link: Surface active user drafts visibly in the Project Portfolio table with direct one-click resume.
5.2 Responsive Split-Screen Layout & Collapsible Navigation
P2 · High
Stakeholder Feedback: "When the browser uses only half of the screen, parts of the page become inaccessible because the content cannot be scrolled horizontally and the navigation panel cannot be collapsed."
  • Collapsible Sidebar: Implement a collapse toggle button reducing the sidebar to compact icon-only mode, expanding main viewport area.
  • Horizontal Scroll Containers: Wrap wide tables, complex forms, and multi-column views in overflow-x-auto wrappers.
  • Fluid Breakpoints: Refine CSS media queries (md: and lg:) so cards, fields, and headers stack gracefully on 50% split-screen desktop windows.
5.3 User Invitation Email & Direct Registration Link Fallback
P3 · Medium
Stakeholder Feedback: "When I created a user, I did not receive an email to continue the registration process."
  • Transactional Email Integration: Wire POST /api/users to SMTP service dispatching an official invitation email with secure activation link.
  • Direct Copy Fallback: Provide a modal dialog upon creation: "User created! Copy activation link to send manually."
5.4 Optional Dark Mode Theme
P4 · Enhancement
Stakeholder Feedback: "A dark mode would be a useful optional improvement."
  • Implement a Light / Dark / System theme switcher in the user profile menu and top navigation bar utilizing Tailwind dark theme tokens.
