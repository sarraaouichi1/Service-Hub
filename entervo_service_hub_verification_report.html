2. Security, Authentication & Role-Based Access Control (RBAC)

The platform employs zero-trust defense-in-depth principles. Authentication and authorization are validated at every boundary.

Authentication Mechanics & Cookie Security

  • Cryptographic Password Hashing: Passwords are hashed using Node.js native scrypt with random salts and calibrated CPU/memory cost factors.
  • Session Token Security: Browser sessions are held in httpOnly, SameSite=lax secure cookies. Raw user IDs are never exposed; the database stores only SHA-256 HMAC tokens. Rotating the session secret instantly revokes all active tokens.
  • Timing Attack & Enumeration Resistance: Non-existent usernames and incorrect passwords return identical 401 error payloads and consume identical execution time.
  • Brute-Force Rate Limiting: Enforces progressive IP and account-level throttling; excess failed attempts trigger 429 Too Many Requests.
  • Lockout Protection: System safeguards prevent the last active administrator from dropping the Admin role, being deactivated, or deleting their own account.
  • CSRF Origin Protection: Mutating requests (POST, PATCH, DELETE) require origin headers matching the server host. Cross-origin requests are blocked with 403 Forbidden.

3. Multi-Product Onboarding Engine & Field Mappings

The Onboarding Engine was completely redesigned to analyze and ingest all 5 product Excel specifications, eliminating repetitive data entry while enforcing strict validation.

Multi-Product Selection & Shared Data Persistence

  • Multi-Product Selection (Step 01): Customers can select multiple entervo smart products simultaneously. The 1st selected product is visibly badged as the Starting Product (⭐ 1st • Starting Product).
  • Cross-Product Auto-Fill: Universal baseline parameters (Operator Name, ID, Address, Country, City, Currency, Cell ID, Name, IP, Port, UI User) are saved to the database draft once and automatically propagated across all products.
  • No Mock Prefill for New Onboardings: Fresh onboardings present clean, empty inputs so customers enter real facility details directly.
  • Persistent Multi-Product Banner: Throughout subsequent steps, a sticky contextual banner reminds users which product they are starting with and confirms shared fields are synced.

Input Validation Matrix

🔢 Numeric & Integer Constraints
Strict digits-only validation on Operator ID, Cell ID, Provider ID (>100), Parking Lots, Charging Stations, Entry/Exit Lanes, and Height Limit. Non-numeric input raises instant inline errors.
🌐 Network & Port Validation
IP address fields require valid IPv4 syntax (0-255.0-255.0-255.0-255). Web and SSH port fields enforce numeric port range constraints (1 to 65535).
📧 Email & Domain Integrity
Contact, Subtech, Incident, and Onboarding addresses require RFC-compliant email formatting. DKIM domain and Portal slugs require alphanumeric hyphen-safe syntax.
🔒 Submission Gating
The final submission requires passing every active step schema and ticking the legal declaration. The server re-executes all schemas independently upon POST /projects/submit.
