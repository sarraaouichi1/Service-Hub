1. The Initial Problem vs. What the Service Hub Solves

1.1 The Operational Deficiencies at the Start

Prior to the development and implementation of the entervo Service Hub, customer onboarding and patch lifecycle management for parking management systems were severely impeded by manual, error-prone workflows:

  • Disparate, Unstandardized Excel Questionnaires: Customer requirements were gathered across disconnected Excel spreadsheets across 6 distinct products (smart web pay, entervo connect, smart validation, mobility CONNECT, smart select, and smart tenant). Each product had distinct field naming and inconsistent formats.
  • Absence of Boundary Validation: Operators submitted invalid IP addresses, missing cell computer parameters, incorrect currency codes, and non-numeric contract IDs. These errors were discovered late during deployment, causing lengthy delays.
  • Financial Clearance Blindspots: Technical teams frequently configured and pre-deployed software before checking whether the customer had paid or if their commercial contract was expired.
  • Role Overlap & Security Gaps: Anyone with system access could approve projects or trigger deployments without governance, creating severe compliance and auditing risks.
  • Unmonitored Patch Rollouts: Parking cell computers had no centralized patch tracking, leaving installations vulnerable to critical zero-day vulnerabilities and uncoordinated maintenance windows.

1.2 The Solution Delivered by entervo Service Hub

The entervo Service Hub transforms these fragmented processes into an enterprise, role-governed web application built on modern web standards (React 19, TypeScript, Fastify 5, Prisma, PostgreSQL 16):

  • Unified 7-Step Guided Onboarding Wizard: Standardizes all 6 product streams into one single source of truth. Shared operator, facility, and cell computer data are safely synchronized in the database.
  • Real-time Zod Format & Contract Verification: Every single field (IPv4 addresses, merchant IDs, VAT codes, ports) is validated both client-side and server-side. Customer contracts are verified with active date enforcement.
  • Strict 3-Role Governance (PM · Sales · DevOps): Role boundaries ensure Project Managers prepare and submit, Sales verifies payment and contract validity, and DevOps performs technical deployment.
  • Centralized Patch Operations Suite: Live Automox cloud orchestration, security bulletins by severity (Critical, High, Medium, Low), automated maintenance window scheduling, and ticket dispatch with strict IPv4 validation.

2. The Three-Role Governance Workflow (RBAC)

To guarantee separation of duties and prevent unauthorized status advancement, the application implements strict role-based access control:

1. Project Manager

Account: manager@scheidt-bachmann.de

Primary Duty: Prepares customer onboarding dossiers and initiates submissions.

  • Access to Dashboard, Projects, New Onboarding
  • Strict Restriction: Cannot view or confirm Sales Delivery Confirmation
  • Strict Restriction: Cannot view or deploy Ready for deployment
2. Sales Team

Account: sales@scheidt-bachmann.de

Primary Duty: Confirms financial clearance and verifies commercial contract validity.

  • Exclusive access to Sales Delivery Confirmation
  • Verifies customer payment and active contract dates
  • Advances cleared requests to approved
  • Strict Restriction: Cannot create drafts or deploy
3. DevOps Team

Account: devops@scheidt-bachmann.de

Primary Duty: Executes technical rollout and cell computer system deployment.

  • Exclusive access to Ready for deployment
  • Access to Patch Management & Bulletins
  • Completes deployment and marks projects onboarded
  • Strict Restriction: Cannot confirm sales checks

3. Tested & Verified Functional Capabilities

3.1 Customer Onboarding & Contract Validity Engine

  • Step 05 Delivery Check & Contract Date: Features an interactive Contract Date / Validity control. If the contract date is expired (past date), the system instantly displays an inline warning notification (⚠ Contract has Expired! Action Required) and disables delivery clearance. If valid, an active verification badge is displayed.
  • Dynamic Summary Data Binding: The conclusion cards beneath Delivery Readiness dynamically display Customer Name, Product Name, PSP, Contract Status, and Sales Contact derived from earlier steps.
  • Secret Credential Scrubbing: Sensitive PSP credentials (pspKey, pspSecret, uiPassword) are write-only. They are accepted by API write endpoints and scrubbed from all read payloads to prevent browser memory exposure.

3.2 Sales Delivery Confirmation Workspace

  • Renamed from Review List: Replaced the generic Review List with a specialized workspace dedicated exclusively to the Sales Team.
  • Explanatory Guidance: Displays a high-visibility banner explaining that customer payment and contract validity must be confirmed before releasing requests to DevOps.
  • One-Click Delivery Clearance: Sales staff inspect details and click "Confirm Delivery & Pass to DevOps", transitioning projects from sales-approval to approved.

3.3 Patch Management & Ticket Validation Engine

  • Remote Access Details Field: Added a dedicated multiline input in Section 3 (Technical Details & Network) capturing VPN profiles, TeamViewer IDs, AnyDesk aliases, and network bastion credentials.
  • Mandatory Customer Input Enforcement: CPQ Order Number, Contract Number, and entervo Software Release start completely blank for customer entry with visible red asterisks (*).
  • Strict Pattern & Type Checking: Contract Number enforces digits-only (/^\d+$/); Number of Devices enforces integer $\ge 1$; Primary, Secondary, and Tertiary IP fields enforce strict IPv4 octet formatting (0-255.0-255.0-255.0-255).

3.4 Platform Administration & Settings Resolution

  • Settings Page Resolution: Fixed the React Query cache mismatch where r.config returned undefined. Both apps/api and apps/web now coordinate on { settings, config } with automated database upsert fallback.
  • Dynamic Rule Enforcement: Admin staff can switch any validation rule between Active/Inactive or Error/Warning with instant zero-downtime server enforcement.
